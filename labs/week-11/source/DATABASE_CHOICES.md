# การตัดสินใจเลือกฐานข้อมูล (Database Choices) — CP41

เอกสารวิเคราะห์และตอบคำถามการเลือกใช้เทคโนโลยีฐานข้อมูลสำหรับระบบ Campus Service Request

---

### 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB?

เนื่องจากข้อมูลคำร้อง (Requests) และผู้ใช้งานในระบบมีโครงสร้างแอตทริบิวต์ที่ชัดเจนและแน่นอน (Structured Data) รวมถึงมีความสัมพันธ์ระหว่างข้อมูลที่ต้องควบคุมความถูกต้องด้วย Constraint และ Foreign Key ซึ่งฐานข้อมูลเชิงสัมพันธ์ (Relational Database) อย่าง SQLite ตอบโจทย์ด้านความสอดคล้องของข้อมูล (Data Integrity) ได้ดีกว่า อีกทั้ง SQLite เป็นระบบฐานข้อมูลแบบ Serverless ที่เก็บข้อมูลไว้ในไฟล์ภายในเครื่อง ไม่ต้องเปิด Database Server หรือต่อเครือข่ายแยก ทำให้สะดวกต่อการพัฒนา ทดสอบ และส่งมอบระบบในแล็บนี้อย่างมาก

---

### 2. ถ้าวันหนึ่งต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง?

การเปลี่ยนไปใช้ MongoDB จะกระทบทั้งชั้น **Service Layer** และ **Controller Layer** ซึ่งต่างจาก 4 ครั้งที่ผ่านมาที่แก้ไขเฉพาะ Service Layer เพียงชั้นเดียว สาเหตุสำคัญมาจาก **ความไม่พร้อมเพรียง (Asynchronous)** โดยไดรเวอร์ของ MongoDB ต้องติดต่อผ่าน Network I/O จึงคืนค่าเป็น Promise ทำให้ฟังก์ชันใน Service Layer ต้องเปลี่ยนเป็น `async function` ทั้งหมด และส่งผลกระทบต่อเนื่องมายัง Controller Layer ที่ต้องปรับใช้ `async/await` เพื่อรอรับผลลัพธ์ รวมถึงต้องจัดการข้อผิดพลาดด้วย Try-Catch เพิ่มเติมด้วย

---

### 3. async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร?

- **จำเป็นเมื่อ:** ฐานข้อมูลอยู่ที่ **คนละเครื่อง** หรือต้องติดต่อผ่านเครือข่ายภายนอก (Network I/O) เช่น MongoDB, MySQL Server หรือ Cloud Database เพราะมีความหน่วงของระบบเครือข่าย (Latency) การใช้ Asynchronous จะช่วยให้ Node.js ไม่เกิดการหยุดชะงัก (Non-blocking I/O) และสามารถสลับไปรับส่งคำขออื่นต่อได้
- **ไม่จำเป็นเมื่อ:** ฐานข้อมูลอยู่ที่ **ในเครื่องเดียวกัน (Local)** ในรูปแบบไฟล์หรือหน่วยความจำ เช่น `node:sqlite` (DatabaseSync) เนื่องจากความเร็วในการอ่านเขียน Local Disk สูงมากและไม่มี Network Latency การประมวลผลแบบ Synchronous จึงทำงานได้ทันทีและทำให้โครงสร้างโค้ดไม่ซับซ้อนโดยไม่จำเป็น
