## ครั้งที่ 1 · การแก้ไขปัญหา CORS และการรันระบบ Full-Stack (CP35 – CP36)

**ถามอะไร**
* การแก้ไขปัญหาเบราว์เซอร์แจ้งเตือน CORS Error (`net::ERR_FAILED` บน preflight request) เมื่อรันระบบร่วมกันระหว่าง Vite (5173) และ Express API (3001) รวมถึงการตรวจสอบการตั้งค่าตัวแปรสภาพแวดล้อม `CORS_ORIGIN` และการเรียงลำดับ Middleware ใน `api/src/app.js`

**AI ตอบว่าอย่างไร (สรุปสั้น)**
* ชี้แจงว่าสาเหตุเกิดจากความไม่ตรงกันของค่า Origin (String mismatch) เช่น ปัญหาอักขระขึ้นบรรทัดใหม่ `\r` (CRLF) ในไฟล์ `.env` บน WSL และการขาดหายไปของ Header ฝั่ง Response เมื่อ Express ยังไม่ได้รับรอง Origin อย่างสมบูรณ์ แนะนำให้ใช้ `sed -i` ตัด `\r` ออก ปรับแต่ง `config.js` ให้ `.trim().replace(/\/$/, '')` และจัดวาง `app.use(cors(...))` ไว้ก่อนหน้าเส้นทาง Route ทั้งหมด

**ใช้ส่วนไหน / แก้เองตรงไหน**
* ตรวจสอบสถานะการทำงานของพอร์ต 3001 และ 5173 ด้วย `curl` และแท็บ Network ด้วยตนเอง, นำคำสั่งกำจัดอักขระ `\r` ไปรันใน Terminal ฝั่ง WSL, ปรับปรุงการกำหนดค่า CORS ใน `api/src/app.js` และทดสอบยิงคำร้องจนหน้าจอ Dashboard แสดงผลข้อมูลสำเร็จ

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2 · เอกสารระบบและวิเคราะห์สถาปัตยกรรม (CP40 – CP41)

**ถามอะไร**
* โครงสร้างเนื้อหา 6 หัวข้อของ `README.md` ตามเกณฑ์ A4 (สถาปัตยกรรม 3 ชั้น, วิธีรัน dev/production, ตาราง env) และแนวทางการตอบคำถามเปรียบเทียบ SQLite กับ MongoDB ใน `DATABASE_CHOICES.md` โดยเฉพาะประเด็นผลกระทบต่อ Controller จาก Asynchronous

**AI ตอบว่าอย่างไร (สรุปสั้น)**
* ให้แนวทางการเขียนเอกสารครอบคลุมแผนภาพ 3-Tier และตารางจำแนกหน้าที่ของแต่ละโฟลเดอร์ พร้อมเฉลยแนวทางการตอบคำถาม 3 ข้อใน `DATABASE_CHOICES.md` โดยเน้นย้ำว่าการเปลี่ยนไปใช้ MongoDB จะกระทบทั้ง Service และ Controller เพราะไดรเวอร์ทำงานผ่านเครือข่ายส่งผลให้ฟังก์ชันกลายเป็น Promise (async/await) ทั้งชุด

**ใช้ส่วนไหน / แก้เองตรงไหน**
* จัดทำไฟล์ `README.md` และปรับปรุงการจัดรูปแบบกล่องข้อความ ASCII และตารางตัวแปรให้เรียบร้อย, เรียบเรียงคำตอบใน `DATABASE_CHOICES.md` ด้วยสำนวนความเข้าใจของตนเอง และเตรียมความพร้อมสำหรับคำถามปากเปล่าเรื่อง async/await

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3 · การเตรียมสาธิตระบบและจำลอง Production (CP42 – CP43)

**ถามอะไร**
* การจัดลำดับขั้นตอนการบันทึกวิดีโอ 2 ช่วง (ช่วง A: สาธิตระบบ 5 ขั้นตอน, ช่วง B: อธิบาย Source Code 5 จุดตามเส้นทางการไหลของข้อมูล) และการแก้ปัญหาเมื่อรันคำสั่งจำลอง Production บนพอร์ตเดียวแล้วหน้าเว็บยังแสดงผลเป็น JSON

**AI ตอบว่าอย่างไร (สรุปสั้น)**
* วางโครงร่างสคริปต์การนำเสนอทั้งสองช่วงและชี้ตำแหน่งบรรทัดสำคัญในโค้ด (เช่น `apiClient.js`, Prepared Statement และ Transaction ใน `requestService.js`, Health Check และบล็อก `if (config.isProd)` ใน `app.js`), อธิบายสาเหตุที่หน้าเว็บไม่ขึ้นเนื่องจากการพิมพ์กำหนดตัวแปร `NODE_ENV` แยกบรรทัดกับคำสั่งรัน ทำให้ต้องรันแบบบรรทัดเดียว `NODE_ENV=production PORT=3001 npm start`

**ใช้ส่วนไหน / แก้เองตรงไหน**
* ซักซ้อมและบันทึกคลิปวิดีโอทั้งช่วง A และ B ตามลำดับที่วางไว้, แก้ไขการรันคำสั่งโหมด Production ให้ส่งค่าตัวแปรในบรรทัดเดียวกันจนหน้าเว็บเปิดผ่านพอร์ต 3001 ได้สำเร็จ, กำหนดค่าสคริปต์ใน root `package.json` และทดสอบรันพอร์ต 10000 เพื่อบันทึกภาพหลักฐาน

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## สรุป

- เข้าใจการบูรณาการระบบ Full-Stack 3 ชั้น (React + Express + SQLite) และความแตกต่างระหว่างโหมด Development (2 พอร์ต + CORS) กับโหมด Production (Single Port เสิร์ฟ Static Files ผ่าน Express)
- เข้าใจการทำงานของ CORS Policy และสาเหตุที่ทำให้ Preflight Request ถูกปฏิเสธ
- เข้าใจการไหลของข้อมูล (Data Flow) ตั้งแต่ UI Component → Service Layer หน้าบ้าน → REST API Routes → Controllers → Service หลังบ้าน → ฐานข้อมูล SQLite
- เข้าใจความสำคัญของ Asynchronous (Network I/O vs Local File) และเหตุผลที่การเปลี่ยนฐานข้อมูลข้ามเครือข่ายส่งผลกระทบต่อเนื่องถึง Controller Layer
- เข้าใจการใช้ Database Transaction (`BEGIN`/`COMMIT`/`ROLLBACK`) และ Prepared Statement เพื่อความปลอดภัยและความสมบูรณ์ของข้อมูล
